# 土地を紹介する100品の選び方

2026-09-26のベルリン記事への指摘を受けた、全都市共通の編集基準。
「その都市で食べられる100品」ではなく「その都市・地域・国の食文化を知る100品」を作る。
国籍だけで料理を排除せず、土地との具体的な関係で判断する。

## 写真を探す前に決める

候補120〜125品を集め、各品を次に分類する。名称を現地語にしただけでは地元料理にならない。

- `city`：都市固有の名物、都市の歴史・名店・生活文化との具体的な関係を裏付けられる品。
- `regional`：周辺地域の郷土料理。地域名と対象都市から取り上げる理由を記録する。
- `national`：対象国の料理・菓子・飲み物・メーカーの商品。どこにでもある料理や飲料を、提供国だけでこの分類にしない。
- `embedded`：国外由来だが、対象都市の歴史・共同体・独自の発展と結び付いて定着した品。都市との関係が書かれた根拠が必要。単一店のメニューに載っているだけでは不足。
- 保留・除外：世界中にある一般的な品、都市との関係が未確認の国外料理、数合わせの付け合わせや材料。原稿に採用せず候補表へ戻す。

標準の編集上の下限・上限として、city/regional/nationalを計80品以上、そのうちcityを10品以上、embeddedを20品以下とする。これは文化を数値で証明する基準ではなく、主役が薄まるのを防ぐ下限。embeddedを20品入れる必要はない。記事ごとに都合よく緩めない。

独立した料理として扱う理由も確かめる。バター、水、果物盛り合わせなどを朝食の部品として分割して数を増やさない。名称・ブランド・地域独自の製法や食べ方が説明できる品へ絞る。飲み物・菓子・スーパーの名物は引き続き採用できる。

## article.json の各料理に selection を必須にする

```json
"selection": {
  "kind": "city",
  "reason": "この都市の記事で取り上げる具体的な理由",
  "distinct": "付け合わせや既採用品の別名でなく独立した一品である理由",
  "evidence": "下記ページで実際に確認できた、料理と土地の関係の要約",
  "sources": ["https://実際に読んだ出典の個別ページ"]
}
```

観光局、地域の食文化資料、歴史資料、メーカーや店の沿革など、主張に対応するページを実際に読む。トップページ、交通案内、空港案内、メニューの存在だけを文化的関係の証拠にしない。出典の文章を読まずにURLやevidenceを埋めない。
本文にも必要な範囲で土地との関係を自然に書く。読者向けに内部の分類や検査項目を表示しない。

`research/dishes.md`に採用・保留・除外とその理由、各分類の集計を残す。写真が見つからないことを理由に、関係の薄い料理へ差し替えない。差し替える場合も選定からやり直す。

## 公開前に止める

`check`は各品のselection、根拠URLの形式、分類の配分を検査する。`post`はこの検査と現在の原稿に対応した選定レビューを必須にし、`--force`でも省略できない。原稿変更後は以前の選定チェックを引き継がない。

自動検査は出典の内容や分類の正しさまでは証明しない。`review`で100品の根拠を一件ずつ読み、一般的な料理を誤分類していないか、名物や菓子・飲料の偏り、数合わせを目視で点検し、`review/selection.md`へ記録する。確認していないチェックを埋めない。

既存記事にも適用する。古い記事はselection未整備のためcheck/postが止まるが、自動で公開状態を変更するものではない。以前の合格を流用せず、再編集時に実際の調査を追加する。
