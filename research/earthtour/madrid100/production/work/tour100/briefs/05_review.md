# ブリーフ4：見直し（review/）

`python3 tour100/build.py review <記事>` で `review/checklist.md` と `out/review/`（料理写真の一覧画像 dishes_*.jpg・scenes.jpg、照らし合わせ用の photos.txt）ができる。次を行って、確かめた項目だけを `[x]` にする。

1. 事実（`review/facts.md`）：
   - 最初に料理の選定を別途 `review/selection.md` に記録する。`SELECTION.md`に従い100品の土地との関係を出典と照合し、数合わせ・一般飲食物・根拠のない国外料理を除く。割合だけ満たして合格にしない。選定チェックは原稿変更で失効する。
   - 各 STOP の店がいま営業しているか、その曜日に開いているか、営業時間。
   - 行き方と移動時間。旅の基本（入国、便、空港、交通、通貨、安全）。
   - 違っていたら article.json を直し、直したことを表に残す（場所・今の文・直した文・出典）。
2. 文章（`review/text.md`）：
   - 導入・本文・写真説明を読み、架空の訪問・注文・実食記録がないことを確認する。公開資料によるモデルコースの説明と本文を一致させる。伝説や異説は区別して残す。
   - 本文資料 `sources` と写真の原典・作者・利用条件を別々に照合する。URLが存在するだけで内容・権利を確認済みにしない。
   - 誤字、表記ゆれ、繰り返し、カード内の矛盾（catch・first・how・tips・phrase の食い違い）、根拠の弱い断定。
   - 見本は `paris-100-dishes/review/text.md`。直した結果を article.json に入れる。
3. 写真：
   - dishes_*.jpg を1枚ずつ見て、番号の料理と photos.txt の料理名・キャプションを照らす。
   - 違う料理、見栄えの悪い写真は `photos.py` で選び直す。
   - その店・その品そのものでない写真は、キャプションに「イメージ」か「別の店」と書く。
4. 画面：`build.py qa` の結果（はみ出し0、画像切れ0、見出しの泣き別れ0）と、out/qa のスクリーンショットを見る。

## 直しの渡し方（どの見直しでも同じ）
直す箇所は、md の表とは別に `review/fixes_<見直しの名前>.json` にも書く。`python3 tour100/build.py fix <記事>` で原稿に入る。
```json
[{"path": "stops[3].dishes[1].catch", "old": "今の文の一部（そのまま写す）", "new": "直した文", "why": "理由と出典"}]
```
- `path` は article.json の中の場所（例 `stops[0].body[1]`、`basics[4][1]`、`meta.lede`）。`old` は今の値に含まれる文字列で、置き換わるのはその部分だけ。
- 数や配列を丸ごと替えるときは、`old` と `new` に JSON の文字列を書く（例 `"old": "2.5", "new": "3.0"`）。
- 入れられなかった直し（原稿がもう変わっていた）は画面に出るので、読み直して書き直す。
