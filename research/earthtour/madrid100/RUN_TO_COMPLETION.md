# 実行指示：マドリード食べ歩き100選を完成させる

## 依頼と到達点

対象は **世界グルメ大図鑑 https://earthtour.jp/**。世界ミステリー図鑑ではない。
添付・同梱の調査資料を使い、「マドリードで楽しむ料理・菓子・食材・飲み物100選」と、食と結び付く名所の案内を、実際に読める記事へ仕上げる。今回は提案や設計書だけで終わらず、追加調査、実写真の確保、本文編集、ページ実装、検査、WordPressの下書き保存まで実行する。
**公開・予約公開・既存公開記事の上書きはしない。**「完成」は、確認済み素材による記事と表示検査を終え、下書きとして保存できた状態を指す。接続などの実際の障害が残る場合は、完成と偽らず、進められる工程を終えて不足と成果物を明示する。

この文書は今回の実行範囲を定める。`source_snapshot/04_Claudeへの引継ぎプロンプト.txt` は前回の調査引継ぎ用であり、今回の工程・下書き保存の範囲は本書に従う。ただし実行環境の上位指示、権限、同じサイトの最新正本を守る。

## 3. 記事の主題と文章

- 主役は **100項目の食**。優先40選は導入の選び方の参考であり、100を40へ削減する指示ではない。名所を料理の項目数に混ぜない。味違い・サイズ違い・同義語で100へ水増ししない。内容の重複が見つかったら、根拠のある代替候補と変更理由を残して100項目を維持する。
- 地域の伝統・州内の産品、マドリードで定番化したもの、他地方・全国由来を区別する。伝統料理であることと、マドリードで発明されたことを同一視しない。「100のマドリード発祥料理」「100軒の店」と書かない。
- 各項目は何か、材料・工程、形・食感の根拠、地域性・歴史、食べられる場面、違いや興味を引く点を、その項目に合う密度で説明する。全項目を同じ文型・同じ字数で埋めない。重要料理は写真と説明を厚くするが、他の項目も料理名と一行だけで終わらせない。
- 実食・訪問・取材を捏造しない。「食べてみると」「店に入ると」「私が訪れた」等の架空体験を書かない。主観的な味は出典に帰属させるか、材料・調理法から説明できる範囲にする。
- 本文から「写真候補」「GREEN」「要確認」「今回調査」「優先度」等の制作メタを除く。読者に必要な季節・予約・アレルギー等の注意は自然に残す。「店で確認しよう」を100回繰り返さない。
- 文字数を増やすための抽象的な煽り、回りくどいAI表現、不自然なたとえ、不要な英語の小見出しを避ける。スペイン語の料理名は必要な情報として残す。
- 店名、価格、提供日、予約条件を出す場合は、実行時点の公式メニュー等で確認し、調査台帳に日付を残す。未確認の価格・最古・唯一・発祥・現在営業中を断定しない。

## 4. 情報の不足を埋める

日本語で概要を押さえ、英語・スペイン語、現地表記・別名・店名・作り手・祭礼名で掘る。市・州の観光局、施設管理者、店の公式メニュー、作り手、生産者団体、地域資料、現地媒体、研究資料を使い分ける。WikipediaやCommonsの説明だけで本文を完結させない。公式観光説明も発祥説の唯一の根拠とせず、主張に合う出典を選ぶ。

出典はURLが開くかだけでなく、本文のどの主張を裏付けるかを確認する。同じ情報の転載は独立した裏付けとして数えない。PDFの図表・メニュー等は該当ページを画像でも確認する。重要な変更は旧記述・新記述・根拠を履歴に残す。

引継ぎの注意を落とさない：コシードの提供を3皿固定にしない。コストラーダの起源年・発明店の食い違いを断定で解消しない。品質表示の計画を取得済みDOP/IGPとしない。蜂蜜の会社所在地と採蜜地を分ける。休館・工事・市場再開・王室厨房の券種と言語は、資料の日付の状態を現在へ無条件に移さず、実行時点の公式案内で確認する。

## 5. 写真の不足を解消する

料理そのものの実写を最優先に、100項目すべての対応写真を探す。写真合計だけでなく料理ごとの充足を管理する。材料・工程・市場・食卓・名所の写真は記事を厚くするために使えるが、料理本体の不足を埋めた数にはしない。

- 既存52件も使用前に原典・画像を再確認する。検索サムネイルを見ただけで採用しない。
- Commonsだけでなく、Flickrの商用利用可能なCC原典、撮影者の公開アルバム、明示的に再利用を認める公的機関・博物館等、素材サイトの個別規約を探す。店・観光局の公式写真は参照可能でも転載許諾があるとは限らない。
- 有料ストック、NC限定、無断転載、許諾待ち、ライセンス不明の写真は使わない。帰属表示だけで利用可能と判断しない。規約が曖昧なら保留する。新規の利用料支払い・許諾依頼送信は別途承認なしに行わない。
- 生成した料理・名所写真、別料理の写真、他国の写真を現地撮影と偽るもの、透かし除去で穴を埋めない。装飾は写真と区別し、既存の利用可能素材を優先する。
- 保存する台帳項目：P-ID、対応M/L-ID、料理／工程／材料等の役割、作者、原典URL、画像URL、ライセンス名と規約URL、取得・確認日、撮影日・撮影地の確認範囲、元サイズ、目視所見、改変内容、クレジット、原画像SHA256、採否・理由、WP attachment IDとWP URL。
- 「不明」は不明と残す。マドリード撮影と証明できない一般料理写真は、その条件が分かる説明にし、特定店の現在の皿として扱わない。古い写真も撮影年・用途を明示して判断し、古いだけで一律に捨てない。
- P019はエントレシホスのみ。P020/P021はCampo Real産の証明ではない。P025はシドラ煮の証明ではない。P042/P043は同じ菓子を切る前後の連続写真ではない。これらの制約を保つ。
- トップは料理そのものが伝わる実写。既存写真は暗いからと即座に捨てず、自然な明るさ・色で整える。存在しない料理の特徴を加えない。改変の可否を確認し、調整を記録・表示する。低解像度を過剰拡大しない。

見つからない料理は、別名・現地語・店名・製造者・行事・材料名などで検索し直す。`work/search_log.csv` に検索語、媒体、結果、採用不可の理由を残す。候補ゼロのまま「探し尽くした」と書かない。無料で商用利用可能な写真を確保できないものは、捏造せず `BLOCKERS.md` に項目単位で残す。未確保を消したり、風景を料理写真に数えたりして完全充足と報告しない。

## 6. 名所は食とつなぐ

名所30件の台帳を維持し、本文では食との関係と読者の回遊に合う場所を選ぶ。王宮と王室厨房、旧市街とイカサンド、菓子と祝祭、アルカラの菓子、アランフエスの農産物など、施設の見どころ自体も説明する。単に料理名の隣へ名所名を置くだけにしない。

市内と近郊を分ける。「近くにある」「徒歩何分」「この店で食べられる」は実際の位置・公式メニュー等で確認する。施設内で売っていない料理を売っているように結び付けない。旅程を出す場合は営業時間・休館日・予約枠・移動手段を照合し、実測していない所要時間は編集上の目安とする。100品全部を短期間で食べる非現実的な旅程にしない。

## 7. 記事を組み、WordPressへ下書き保存する

最新のグルメ側正本に沿って実装する。資料の `Madrid_本文と写真_統合版.html` は閲覧用であり、WordPress用テンプレートではない。ミステリー用のCSS、暗い背景、公開装置をそのまま流用しない。

料理別アンカー、読みやすい目次、最初の一食を選べる導入、100項目の章、食と名所の案内、必要な季節情報、出典・写真クレジットを整える。100枚の同じカードを並べるだけにせず、本文を細切れにしすぎない。見出しの孤立、過大な余白、出典の重複、英語の装飾見出し、フォント混在を点検する。重要文の強調は正本の基準で節度を保つ。本文・写真・出典の役割を混ぜない。

写真は権利確認と目視のあとに原画像を保存し、実環境で利用可能な earthtour.jp の標準アップロード経路を確認して使う。過去のBulk Media Importer手順は手がかりであり、現行と決めつけない。重複を照合し、health確認、少数の試験投入、取得結果の確認を行ってから必要分を追加する。未確認画像を一括投入せず、失敗分だけ再試行する。認証情報をチャット・Git・台帳・ログへ書かない。

下書きを保存したらRESTまたは管理画面で本文・画像・アイキャッチ・status=draft・IDを読み戻す。既存の同じ下書きを再利用した場合は変更前の内容を安全な作業領域にバックアップする。下書きプレビューには適切な認証を使い、確認用の一時公開はしない。

## 8. 検査して直す

自動検査だけでなく、ブラウザで実際に見る。少なくとも幅360・390・768・1024・1440pxで、横はみ出し、文字切れ、表、写真比率、余白、目次、アンカー、出典リンク、画像欠けを確認する。H1がページ全体で重複していないかも調べる。外部画像はlazy-load分も含めて確認する。最初の画面、途中の高密度部分、末尾の出典まで見る。スマホとPCのスクリーンショットを残す。

ローカルプレビューとWordPress下書きは別に検査する。WP接続できずローカルのみ確認した場合、それを本番環境の表示確認済みと呼ばない。情報検査、写真権利、文章・構成、視覚デザイン、技術表示を分けて点検し、問題を修正して再検査する。自動PASSをそのまま「すべて正しい」と言い換えない。

## 9. 保存物と完了判定

成果物は正本の構成を尊重しつつ、少なくとも本文の編集元、生成HTML、更新した構造化台帳、使用写真と権利・WP対応表、調査ログ、表示検査結果、引継ぎ情報が追える形で保存する。原画像の大量Git投入は必須にせず、利用条件とリポジトリ容量に沿って管理する。出典の有料全文や機密情報は保存しない。

`STATUS.md` に工程別の進捗、`BLOCKERS.md` に本当に残る問題、`qa/report.md` に検査結果と証拠の所在、`handoff.json` に記事ID・status・プレビューの扱い・対象サイト・コミットSHA・残作業を残す。認証付きプレビューURL等は公開リポジトリに記載しない。

完了時に確認すること：
1. 食の100項目があり、内容重複や参照切れがなく、それぞれ根拠のある紹介文に仕上がっている。
2. 採用した名所の見どころと食の関係が説明され、市内と近郊、事実と目安を分けている。
3. 使用画像すべてについて、被写体・権利・クレジット・保存先を確認できる。料理別の写真充足と不足を正確に報告する。
4. 残す価格・提供状況・工事等は実行時点の根拠を持ち、架空の実食や管理メタが本文に残っていない。
5. WordPress下書きの読み戻しとスマホ・PC表示を確認し、未修正の重大な表示不具合がない。
6. 成果物が保存され、権限のある環境ではGitHubへcommit/pushされ、取得し直して実在を確認できる。

写真不足・権利不明・出典未確認・WP未接続・未実施QAがあるのに「完全完成」「公開準備完了」と書かない。工程別に完成と未完了を分ける。権限・利用制限・無料素材不在など実際の障害がある場合も、依存しない工程は可能な限り終える。

途中で「次をやりますか」と何度も止めず、追加調査から修正・保存まで続ける。実行時間・文脈の制約が近づいたら、未完了を隠さず、再開箇所と成果物を保存する。実際の予約やジョブを作っていないのに、裏で続ける・後で届けると約束しない。

最終報告は、記事とGitHubの実在する保存先、100項目の本文状態、料理写真の充足数・不足ID、名所の採用数、WP下書きID・状態、表示検査の結果、残る問題に絞る。計画だけ、プロンプトの書き直しだけ、短い見本だけで終了しない。
